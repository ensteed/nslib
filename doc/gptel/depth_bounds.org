*Depth bounds testing* is a fixed-function fragment processing stage that discards fragments based on their existing depth buffer value.

*** Purpose:
It allows you to define a range =[minDepthBounds, maxDepthBounds]=. If the depth value already in the depth buffer for a pixel falls outside this range, the fragment is discarded.

*** Primary Use Case:
-   *Deferred Shading Optimization:* It is commonly used to limit light calculations to a specific "slice" of the scene. By setting the bounds to the volume a light occupies, you can avoid expensive shading operations for pixels that are clearly in front of or behind the light's influence.

*** Key Requirements:
-   It must be supported by the hardware (=VkPhysicalDeviceFeatures.depthBounds=).
-   It is enabled via =VkPipelineDepthStencilStateCreateInfo=.
-   Bounds are set dynamically using =vkCmdSetDepthBounds=.

No, *depth bounds testing is not supported* on the Raspberry Pi 5 (VideoCore VII GPU).

The =depthBounds= feature is an optional part of the Vulkan specification, and the *V3DV* driver (used for Raspberry Pi) reports this feature as =VK_FALSE=.

*** Why?
Depth bounds testing is common on "Immediate Mode" desktop GPUs (NVIDIA, AMD, Intel). However, the Raspberry Pi uses a *Tile-Based Deferred Renderer (TBDR)*. Most mobile-oriented tiled architectures do not implement this specific hardware check.

*** What should you use instead?
Since you can't use =depthBounds=, you have two main options for optimizing light volumes on the Pi 5:

1.  *Stencil Buffer:* Use the "Stencil Volume" technique. Render the light's bounding mesh to the stencil buffer first to mark pixels that fall within the depth range, then render the light only where the stencil passes.
2.  *Shader-based Discard:* Inside your fragment shader, manually fetch the depth value from the G-Buffer, compare it against your light's min/max distance, and call =discard;=. 
    *   /Note:/ This is less efficient than hardware depth bounds because the shader still has to start executing, but it's the standard workaround on hardware without =depthBounds= support.
